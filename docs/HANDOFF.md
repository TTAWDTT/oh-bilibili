# BiliMusic 交接说明

这份文件写给接手的人（包括未来的我）。它记录当前状态、怎么跑、哪些是坑。

## 待验收清单（这一轮改动）

解锁后按顺序跑一遍，都是本轮动过、但只能在真机上看的地方：

1. **每周必看**：左侧「每周必看」→ 应为第 399 期 `等待一生的巨浪 / 第399期(1113更新)`，50 条；点 `‹` 回第 398 期、点 `›` 回来，最末期号时 `›` 置灰。
2. **发现页连滚**：一直往下滑，不该再出现「推荐到底了」反复闪烁；控制台不该有 `Maximum update depth`。这一条修的是推荐流整批重复时的无限重取。
3. **观看页**：进出视频几次，退出后声音必须停；播放一小时的视频，滚动评论区不该顿。
4. **长列表预取**：搜索结果连续甩二十秒，中途不该停在「正在加载更多…」；真撞上限流会出现「没加载出来，重试这一页」，点它能继续。
5. **关注页**：翻页失败时列表还在，原地出现「没取到，重试」，不是整页变错误态。
6. **观看页返回**：返回在顶栏（logo 换成 `‹ 返回`），不压在画面上；观看页不挂侧栏，主区从 0 起画。
   进出视频几次，左边不该残留一条点不动的旧侧栏（WebKit 合成层没回收，靠主区自己铺底盖掉）。
7. **窄窗口（拖到 768 以下）**：底部「发现」必须回发现页；「我的」页有历史 / 收藏夹 / 稍后再看 / 关注四个入口；换歌时全屏歌词面板不再自动弹出来。
8. **窗口化列表**：搜索后停着不动，「已加载」会涨到 1200 以上，但页面只挂两百多张卡；连续下滑时新卡要立刻接上，底部不该停在「正在加载更多…」；点进视频再返回，要落回原来那张卡附近，而不是跳回顶部。
9. **观看页工具栏**：点赞 / 投币 / 收藏 / 分享 是一排无边框的图标行，悬停才有浅底；分享点一下复制 BV 链接；进度条是主题蓝。
10. **发现页站脚**：滑到最底部有「哔哩哔哩 (゜-゜)つロ 干杯~」。
11. **观看页右栏**：从上到下是 UP 名片（头像 / 名字 / LV / 大会员 / 认证 / 签名 / 关注）→ 弹幕列表（展开后点一条能跳到那一刻）→ 合集 → 相关推荐；窗口拖到 768 以下，UP 名片回到正文标签下面。
12. **顶栏投稿**：最右边那颗主题蓝「投稿」点开是 B 站官方上传页（系统浏览器）。
13. **发现页频道条**：白色 header 带里是左边两个圆入口（热门 / 排行）+ 右侧一排 12 个窄胶囊（含「汽车」），
    1320 宽下必须排成一行、不折行。胶囊按 B 站原版做成 #f6f7f8 无描边 + 深色字 + 28 高 / 62 宽，
    左缘和轮播、卡片同一条线；和左栏重复的快捷入口已删除。
14. **换一换**：轮播右侧竖排按钮只换首屏那十一条（轮播 5 + 右栏 6），带 240ms 淡入；下面「推荐」流与滚动位置不动。
    列表末尾的「换一批」才是整页重来。
15. **侧栏选中态**：当前页只有浅蓝底与主题蓝文字/图标，不挂左侧竖线；悬停也不出竖线。
    全站只用一种主色：蓝色。旧的 33 娘粉已退役，`--bili-pink` 变量已删除。
16. **播放器控制条**：按钮 36×22、时间字 12px 白 80%、底部内边距 6px；未登录时弹幕条是「请先 登录 或 注册」而不是输入框。
17. **发现页首屏比例**：宽屏下 45/55 分栏、轮播 7:5，右侧 3 列 × 2 行六张卡，轮播底边和右栏底边收在同一条线上
    （1320 宽实测齐平）；换一换按钮 `self-stretch` 拉满整列高度。
18. **首屏右侧六卡**：封面左下角播放 / 弹幕计数、右下角时长；标题 13.5px 两行，作者行前有 `UP` 小徽标。
19. **排行榜分区 tab**：灰底无描边胶囊，选中的是蓝色描边 + 蓝字，和发现页频道胶囊同一套画法。
20. **推荐流密度**：1320 宽下推荐流应为 5 列（卡片约 195），作者行是 `UP` 小徽标 + 名字，和首屏右侧四卡一致。
21. **三连微交互**：观看页和卡片动作排的点赞/投币/收藏点中时，图标分别弹一下、翻面、转一圈（320–420ms）；系统开启减少动态效果时不播放。
22. **三连状态可读**：点赞和收藏未点亮时是空心线稿，点亮才填实变蓝（真机验过：空心灰 → 点一次变实心蓝 → 再点回空心）。
23. **右栏相关推荐**：每行封面右下角有真实时长（曾整列显示 0:00，根因是接口按秒下发、解析时漏乘 1000），
    UP 名右边有播放和弹幕两枚计数。离线回归见 `crates/bili/tests/live.rs` 的 `相关推荐的时长是毫秒不是秒`。
24. **右栏 UP 名片**：充电（描边）和关注（实心）两颗窄胶囊靠右，同用主题蓝，不再是一条占满整行的色带。
25. **右栏弹幕列表**：展开后每条带时间点、可点击跳转，文字用弹幕自己的颜色；纯白和浅色回落到主题色，否则在白底上看不见。
26. **排行榜头部**：白色 header 带里是标题、一行「榜单根据稿件内容质量与近期数据综合排序，动态更新」、一排文字 tab
    （选中项挂蓝色下划线，横向可滑），和 B 站排行榜页一致。榜单正文是**两列横排列表**：左封面（168 宽，左上角压名次，
    1 蓝 / 2 橙 / 3 黄、其余半透明黑）右标题 + UP + 播放/弹幕，不套发现页的卡片网格。
27. **热门页**：白色 header 带（标题 + 「各个领域中新奇好玩的优质内容都在这里~」+ 右侧「热门规则」）；

    标题下方是 B 站自己的橙色描边小标签（「百万播放」「人气飙升」「7万点赞」），来自 popular 接口的
    `rcmd_reason.content`；这个字段在热门是对象、在每周必看是裸字符串，两处解析分开

28. **入站必刷**：与热门共用 `features/tracks/WideCard.tsx`，白带里标题是接口给的「我不允许还有人没看过这98个宝藏视频！」；

29. **每周必看**：白带里是「主题」、一行「每周五晚 18:00 更新」、‹ › 翻期与「第N期(日期更新) ▾」下拉；

30. **观看页弹幕**：位移距离按播放器容器宽度算（之前写死 `100vw`，播放器比窗口窄时后半程在画面外空跑），

31. **评论头行**：右侧统一是「拇指 赞数 + 拇指朝下」，零赞也占位，和 B 站每条评论同一个形状。
32. **顶栏搜索建议**：聚焦且输入为空时落下面板，上半是本地搜索历史（可清空），下半「大家都在搜」前十
    （`search/square`，前三名蓝字）；点词直接进搜索结果，取不到热搜只显示历史、面板不挂。
33. **顶栏频道**：logo 右侧「首页 / 番剧 / 直播」纯文字，`xl` 以上出现；窄窗收起来，不和搜索框抢位置。
34. **观看页信息顺序**：标题 + 统计行在播放器**上方**（「N 人在看」也在这一行）；播放器之后依次是三连、

35. **观看页收藏**：未收藏先弹 B 站那套「收藏到」面板（真实收藏夹 + 每个夹的视频数），选夹后才写；

38. **UP 主空间**：进空间时先查一次真实关注关系，已关注的 UP 显示「✓ 已关注」而不是「+ 关注」，
    点它可以直接取关。
39. **分区子菜单**：发现页那排分区胶囊，悬停或聚焦后落下 B 站那块子分区面板（600 宽、4 列，
     MAD·AMV / VOCALOID·UTAU / 鬼畜调教 这类原名）。面板贴着被悬停的胶囊，靠近右边缘时自动左移。

40. **动态**：侧栏「发现」下面的新页，读关注 UP 的最新投稿（`feed/all`，一次 20 条，游标 `offset` 续页）。

    显示「已关注」并禁用，不用先点一下才知道。未登录或取不到时保持原样，不拦搜索。
42. **观看页分享**：点分享不再直接复制，弹出 B 站那块小面板，三行分别是复制链接、复制 BV 号、
    在浏览器打开。投币与分享共用 `shared/ui/AnchoredPanel`，贴着按钮展开，靠近底部时向上翻。
43. **热搜角标**：搜索页热搜榜与顶栏建议面板都显示 B 站给的角标图（热 / 爆 / 独家 / 新），
    点一条按接口的 `keyword` 搜，展示名只负责显示。建议面板条目的动作改走 onClick（按下时只挡 blur），
    键盘与辅助技术也能触发，不再只认鼠标按下。
44. **直播首屏**：页头只留「直播 + LIVE」与右侧「全部直播」，下面是第一间房的宽幅焦点位
    （封面、直播中、标题、主播头像、人气、在浏览器打开），其余房间从下一张卡开始排。
    直播流仍不在客户端内解码，所有入口都如实交给系统浏览器。

45. **消息中心**：顶栏描边消息图标带主题蓝未读角标，侧栏「动态」后增加「消息」。
    760px 居中消息页提供「回复我的 / @我的 / 收到的赞」三个分类，切换即取第 1 页。
    真实接口为 `x/msgfeed/unread`、`x/msgfeed/reply`、`x/msgfeed/at`、`x/msgfeed/like`，
    列表带 `platform=web&build=0&mobi_app=web&pn=页码&ps=20`，请求间隔 400ms。
    获赞读 `data.total.items` 和 `data.total.cursor.is_end`，另两类读 `data.items` 和 `data.cursor.is_end`。
    未读总数只加 reply、at、like，登录和进入消息页时刷新，失败静默；分类未读为 0 时不显示数字。
    回复和 @ 展示头像、用户名、时间、引用评论与视频卡，获赞最多叠放 3 个头像并显示总人数。
    点用户进主页，视频 URI 在 bili 层提取 BV 号后进入观看页，其他链接交给浏览器。
    未登录拉起登录框；首屏使用小电视加载，空态用 2233 娘，失败可重试。
    离底部 600px 自动续页，保留「加载更多」；切分类后旧请求不会回写当前列表。

## 一句话现状

能跑通的 B 站桌面客户端。搜索、播放、歌单、歌词、弹幕、下载、历史、收藏夹、关注、动态和消息中心都能用，
UI 按 B 站网页端的视觉语言做（浅色底、B 站蓝、封面卡片、分区标签、三连按钮）。

## 架构要点

五个 crate，依赖方向由 `crates/core/tests/deps.rs` 用 `cargo metadata` 断言。

```
model  ← bili / store / audio
       ← core ← apps/desktop/src-tauri
```

四条必须遵守的规矩：

1. **播放位置的真值只在声卡侧**（`Clock` 原子帧计数），状态机里没有 position 字段。
2. **wire 类型不出 `bili`**：B 站的 JSON 在适配层内解析成领域类型。
3. **队列身份是 `EntryId` 不是下标**，重排与随机不会互相踩。
4. **Rust 与 TS 字段名必须一致**，`crates/core/tests/contract.rs` 双向断言。

## 已知的坑（都实测过）

| 问题 | 现象 | 处理 |
|---|---|---|
| 图片 CDN 校验 Referer | webview 里封面全部裂图 | `<img>` 必须加 `referrerPolicy="no-referrer"` |
| 视频 CDN 必须带 bilibili Referer | `<video>` 一律 403 | 走本地代理 `mv.rs`，它补 Referer 与 Cookie |
| 弹幕接口返回 deflate 压缩的 XML | 当文本解析得到 0 条 | 先 `flate2` 解压再解析 |
| 音乐区用子分区 id | 按主类目 3 筛得到 0 条 | 音乐 = `3,28,29,30,31,59,130,193,171` |
| ~~`tids` 参数已失效~~ | **这条结论是错的**：当时返回 0 条其实是撞上限流 | `tids` 传一级分区 id 完全有效（音乐 3、游戏 4），已改回服务端过滤 |
| 搜索接口的页面守卫 | 按分钟窗口限请求数，不是按间隔算 | 实测 9 秒连翻 24 页、一分钟内四十多页仍然条条有货；间隔保持 400ms，预取封顶五十六页（`PREFETCH_PX = 180000`），翻页失败给「重试这一页」入口，不把列表当成到底 |
| 收藏夹列表不带封面 | `created/list-all` 没有 `cover`，逐个夹子取封面要 5 秒以上，首屏一片灰 | 列表走 `created/list`（自带每个夹子的 `cover`），四宫格拼图后台补 |
| 观看页换片会压历史栈 | 相关推荐/自动连播用 `navigate`，返回要穿过一整条视频链 | 观看页内换片走 `replace`；发现页、搜索页、排行榜分区都把状态写进视图或会话缓存 |
| 播放进度可能串轨 | 引擎还停在上一条时，界面读出别人的时钟，出现 `0:37 / 0:15` | 读进度前先比对 snapshot 的 track key，不是本条就归零 |
| 端到端测试的等待窗口 | 网络慢时假红 | 等 3 秒、断言位置 > 800ms |

## 接口可用性的实测结论

早期这里记着「被风控挡住」，后来重验发现大部分是误判。当前实测：

| 接口 | 状态 | 说明 |
|---|---|---|
| `x/web-interface/card?mid=` | ✅ 可用 | UP 主粉丝数、签名、认证。不需要登录，不需要 wbi |
| `x/relation/stat?vmid=` | ✅ 可用 | 关注数、粉丝数 |
| 搜索 `tids=` | ✅ 可用 | 一级分区过滤 |
| `x/space/wbi/acc/info` | ⚠️ -352/-799 | 等级徽章仍拿不到；`card` 里没有 level 字段 |
| `x/space/arc/search`（无 wbi） | ⚠️ -412 | 缺 buvid 指纹时被 ban；带上 buvid 变 -799 限流 |
| `x/space/wbi/arc/search` | ⚠️ -403 | 访问权限不足，需要登录态 |

**教训**：撞到限流返回的空结果，很容易被当成「接口失效」。
下结论前应该换一组参数、等一会再试一次，或者换个等价接口。

窄屏改动的几个坑，改之前先看一眼：

- **改间距不会生效**：播放队列的行高来自 `QUEUE_ROW_HEIGHT` 常量（虚拟列表要求固定高度），
  在 className 里加 `py-*` 会被它截掉。
- **hook 不能放在提前 return 之后**：`StageView` 里 `useSwipe` 放错位置会让两次渲染的
  hook 数量不一致，整个舞台白屏。
- **`env(safe-area-inset-*)` 在桌面上是 0**，加在顶栏和底栏上对桌面没有影响。
- **窗口最小尺寸**是 `tauri.conf.json` 的 `minWidth`，不放开就拖不到手机宽度。

### 没验过的

（取消点赞需要传 `like=2` 这一条已经验过了，见下一节，这里不重复。）

- **扫码登录**：需要你本人扫码，自动化没法代替。
- **投币、关注 / 取关**：都是写真实账号，投币不可逆，关注会给 UP 主发通知，
  所以只在真机手点过，不在自动化里跑往返。
- **UP 主投稿**：已接 `space/wbi/arc/search`（WBI 签名，code 0）。只有拿不到 mid
  的场合才退回「按作者名搜索」，那时界面会明确标注不是完整投稿列表。
- **长时间压测**：内存只做了 60 秒采样（91–93MB 稳定）与切歌 5 次（100MB），

## 已修复：取消点赞要传 like=2

踩了很久的一个坑，记下来免得再踩。

原文的症状：取消点赞恒定返回 `-400 请求错误`，而点赞正常。

真正的原因只有一个：**B 站取消点赞传的是 `like=2`，不是 `like=0`**。传 0 会被判成非法参数。

排查过程中排除掉的（都不成立）：csrf 失效（同一条 `bili_jct` 打评论接口能过校验）、缺 WBI 签名（补了 `w_rid`+`wts` 仍 400）、冷却（等 70 秒仍 400）、编码问题（form / JSON 都试过）、缺 `bvid`/`type`/`oper`/`mobi_app`。

网页端还会带 `eab_x=1`、`ramval=9`、`source=web_normal`、`ga=1`，现在一并带上。

`crates/core/tests/live_engine.rs` 的 `点赞能写入也能取消` 做往返验证，顺序是「读原状 → 改成反面 → 校验 → 改回原状 → 校验」，跑完不留痕迹。
